# Reverse 3D

Input: a finished video (3 to 10 seconds). Longer clips are trimmed to the first 10 seconds. Kling 4.0 Edit allows 3-30 seconds and keeps the input length; 10 seconds is the longest we send. The browser isolates the main subject in one frame and builds a gray box mesh of that subject. The run uploads a PNG of the current view as Kling's reference image (`@Image1`).

Output: a blocky Blender-viewport playblast restyle via Kling 4.0 Edit. The side-by-side compare (original left, playblast right) is built in the browser so the graph does not OOM stitching frames. The first frame is dropped on both sides because Kling’s frame 0 is often smeared.

This workflow is playblast-only: LoadVideo → GetVideoComponents → ResizeAndPadImage → CreateVideo (constant 24 fps, original audio) → Kling4EditVideoNode → SaveVideo. LoadImage (node 12) is the browser mesh, wired to `model.reference_images.image_1`. Browser MediaRecorder WebMs often have no duration and confuse LoadVideo into reporting 1 fps; re-wrapping the decoded frames at 24 fps keeps the frame count and satisfies Kling’s 24 fps minimum without stitching (which OOMs).

Kling 4.0 Edit requires both sides between 700 and 4553 pixels and a width/height ratio from 0.40 to 2.50. Node 17 runs on every clip. The server sets its canvas from the file: MP4/MOV sample size, swapped when the track matrix is 90° or 270° so it matches the frames LoadVideo rotates, and WebM PixelWidth/PixelHeight even when the Segment size is the 8-byte unknown length Chrome MediaRecorder writes. It scales uniformly until both sides are at least 700, keeps an already-legal frame as-is up to 1920×1080, and pads with black only when the ratio is outside 0.40–2.50 (smallest legal canvas, 700×1750 or 1750×700). Nothing is cropped or stretched. The long side stays at or under 1920 so a 10 second 24 fps batch does not grow toward Kling’s 4553px ceiling.

## Browser subject

The polygon slider never calls the server. Dragging it rebuilds the subject mesh in the page. Run posts a PNG of that view, as it looks on screen (orbit angle and polygon count), on the existing `POST /api/run/reverse-3d` field `scene`. The server still resizes it and attaches it to node 12.

**Which frame.** Up to 12 frames are taken across the accepted duration (the first 10 seconds). Each frame is drawn down so the long side is 96 pixels. The background is whatever color the border mostly is. Pixels close to that color flood in from the border. What the flood cannot reach is foreground. Objects smaller than 1.5% of the frame are ignored. The largest remaining object is the subject, and any other object is dropped. A frame scores higher when that subject is a moderate fraction of the picture, clearly different from the border, not touching the left, right, or top edge, and not competing with several similar objects. The highest score wins. A tie keeps the earlier frame.

**The mesh.** Only that silhouette becomes boxes. Each occupied cell is a cube, inset so the seams stay visible. The cube is thicker toward the middle of the silhouette and one box deep at the outline, and the back is the same hull mirrored. There is no smooth surface and no photograph color: every face is flat gray. The slider runs from a few huge boxes up to about 30% of the subject's pixel span, so the right end is still chunky. Dragging left makes the boxes bigger. The label shows the exact triangle count. Nothing is sent to a server for that change. Orbit is a drag on the canvas; the same view is what Run captures. BiRefNet is not used here, because the only copy in this repo runs as a paid Comfy job. The mask is the free border flood above. If a frame has no foreground, the mesh falls back to a plain upright stack of boxes.

**Where it looks wrong.** This is not a depth model and it does not know what a person is. A crowd becomes the single largest blob, which may be several people overlapping, and the others disappear. A clip with no clear subject (a landscape, a title card, fog, or a frame that matches its own border) gets the fallback stack or a weak shape. A flat product, poster, or screen that fills the frame becomes a slab of boxes, not a character. A subject the same color as the wall is swallowed by the background flood. Shadows, reflections, and a prop that touches the body stay in the silhouette; a prop with a visible gap is dropped. Overlapping limbs and the hidden side are the boxy hull of one view, not a scan. The reference still is whatever angle is on screen at Run. A container with no duration and no cluster timestamps is rejected; a file whose timestamps claim a short length is accepted even if the pictures run longer.
